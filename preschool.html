66 天幼小衔接训练营 · 内容 + 配图系统

一个真实项目：66 天训练营的「内容规划 + 插画配图 + 微信每日推送交付」。核心是识别"66 张风格一致插画"才是真成本，于是把设计语言沉淀成可复用库，并在关键时调用适配。

独立项目风格库沉淀Day11 一线诊断
项目边界声明（重要）：本项目是一个独立项目，不是「设计总监风格库 / 风格提取库」（那是一个完全不同、尚未落地的项目构想）。本项目的风格、客户画像、客户需求只属于本项目，不可套用到其他项目。可跨项目复用的只有方法论逻辑。

1. 背景（真实项目是什么）

一个 66 天幼小衔接训练营：每天给家长/孩子推送一篇主题内容（习惯养成、识字准备、情绪管理等），通过微信小程序 + 每日定时推送触达。核心生产痛点是——66 篇内容要配 66 张风格一致的插画，纯手工出图慢且风格漂移。

2. 我做了什么（端到端落地）

环节产物作用
内容规划content/planned/day*.json（56 个 day）每个 day 含 visualHint（中文视觉提示）
风格沉淀style.md把视觉风格定义成可复用规范（配色/光线/氛围/表情关键词库 + Day1–6 锚）
提取extract_hints.py从内容规划批量提取每个 day 的 visualHint
关键时调用适配build_prompts.py锁风格后缀，把中文 visualHint 适配成英文 SDXL prompt
交付自动化publish.js + 云函数 + 微信每日推送配图 → 写入 → 定时发布全链路
一线诊断diagnosis-day11.md定位「Day11 没完成」真因

3. 三个关键能力

进现场摸需求（Echo）

识别真痛点：不是「不会画」，是「66 张要一致、要每天稳定产出」。风格漂移 + 人工瓶颈才是成本。于是把「设计语言」从个人脑子里沉淀成可复用资产，让出图可规模化、可复现。

端到端 Forward Deploy（Delta）

把「风格库 + 提取 + 调用适配 + 推送」整个链路自己端到端搭起来并跑通，不是只写一份 PRD 交给别人。

一线诊断

Day11 内容「没发出去」。用第一性原理追问后发现：真瓶颈在交付出口（小程序未备案，发布接口被限），不在出图/推送流水线本身。这决定了修复优先级。

4. 交付与结果

交付物：一套跑通的内容生产 + 配图系统——内容规划（56 个 day）、风格库（style.md）、批量提取（extract_hints.py）、关键时调用适配（build_prompts.py）、微信每日推送全链路，以及 Day11 一线诊断文档。

结果：66 张风格一致插画从"纯手工、易漂移"变成可规模化、可复现的产出；Day11 诊断把修复优先级从"优化已能跑的流水线"纠正到"解决备案/出口"，避免在无谓方向浪费资源。这套方法论（把一类设计语言沉淀成库、关键时锁风格后缀做调用适配）可迁移到「给设计总监做风格库沉淀」场景——但迁移的只能是逻辑，不是细节。
