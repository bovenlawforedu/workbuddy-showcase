0-1 AI 系统 · RAG 不幻觉原型

企业内飞书智能客服机器人（RAG 原型）

给企业内部做飞书 @机器人：员工基于公司私有资料（产品手册 / 售后政策 / FAQ）提问，机器人只依据私有资料作答、不幻觉、每条带引用；答不出的高频问题自动上报，补完资料后自动下发当初提问的员工。已做成一个面试官易看、非技术也能看懂的可交互 Demo + 架构图 + 静态展示页。

RAG 系统不幻觉飞书 OpenAPI零依赖可交付

▶ 在线 Demo / 展示页    ⌨ 公开仓库

项目边界声明（重要）：本项目是企业内部「智能客服」方向的 RAG 原型 / 面试作品，核心交付是可交互 Demo + 架构图 + 静态展示页，而非只交代码。内部材料（FDE 计划 / 演示稿 / 客户沟通）不进公开仓库。

1. 背景（要解决什么）

企业资料散落在 Word / PDF / 网页里，员工遇到产品、售后、政策类问题找不到答案，只能到处问人。直接调大模型又会编造、且私有资料出域有合规风险。于是选 RAG（检索增强生成） 而非裸调大模型：只依据私有资料作答、可控引用、资料隔离不出域。

2. 我做了什么（端到端落地）

环节产物作用
检索中文 bigram 分词 + BM25解决单字 BM25 误命中，把可答(21+)与不可答(3–6)分离，MIN_SCORE=10
内容护栏guard.py无信源仍硬答 → 问"联系谁"但资料无联系人时拒答并上报
身份识别飞书 open_id → 通讯录 → 岗位映射免手动选岗，按岗位自动识别与改写提问
多格式解析pypdf + python-docx + stdlib HTMLParser避开解析依赖地狱，统一抽私有资料
可交付运行零依赖 Web 服务 python app.py → localhost:8000预构建 index.json + 标准库 http.server，任意 Python3 一键可跑；LLM 可插拔
未答闭环高频未答看板 + 自动下发答不出的高频问题上报，补完资料后自动下发当初提问员工

3. 三个关键能力

不幻觉三层防御

单字 BM25 误命中 → 中文 bigram 分词；无信源仍硬答 → guard.py 内容护栏拒答；身份需手动选岗 → 飞书 open_id 自动映射。黄金集评测 12/12 = 100% 不幻觉准确率。

面向非技术受众的双轨交付

Web 行为模拟器（主交付，面试官/非技术直接看）+ 真实飞书接入代码（技术附件），把"能跑"翻译成任何人都能看懂的演示。

高频未答闭环的产品思维

机器人答不出的问题不是终点：自动上报成看板，补完资料后把答案下发回当初提问的员工——把"客服机器人"做成持续变聪明的系统，而不只是一次性问答。

4. 交付与结果

交付物：零依赖 Web 服务（飞书 @机器人 行为模拟器）、自动身份识别 / 模糊提问按岗改写 / 不幻觉拒答 / 闭环下发 全验证、静态展示页（架构图 + 7 段真实对话）、真实飞书接入代码 feishu_bot.py、公开仓库与 GitHub Pages。

结果：黄金集评测 12/12 = 100% 不幻觉准确率；私有资料隔离不出域、零三方依赖保证任意环境一键可跑；把"企业智能客服"这么个说不清的需求，落地成了一个能演示、能验证的原型。

与 AI Product Builder / FDE 岗位的对应

FDE / Builder 能力本项目证据
进现场摸真实需求识别"资料散落、员工找不到答案"是真痛点，而非堆一个聊天框
端到端 Forward Deploy检索→护栏→识别→解析→可交付运行→未答闭环，全链路自己搭通
安全与治理前置RAG 资料隔离不出域、不幻觉三层防御、私有资料合规
面向受众的交付双轨交付：非技术看 Demo、技术看代码，降低沟通成本
关于「复用」的纪律：本项目的"不幻觉三层防御 / 闭环下发 / 双轨交付"是方法论逻辑，可迁移到任意企业知识问答场景；但具体的资料、岗位、业务语言只属于本案例，换项目必须重新进现场定义。
