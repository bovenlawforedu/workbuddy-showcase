会议英语反应力训练 · Say得出

给"开会会一点英语、但不敢开口"的职场人，做了个 7 天反应力训练 Web app。这也是 FDE 那种"不写方案、自己从一头到另一头搭起来跑通"的例子：从修数据闭环里的假数据、把反应时间按方法学校正，到安卓触屏按住说话跑稳、手机端 HTTPS 真机可点——全是我自己跑通、一路迭代到 v1.3.3。

1. 背景与约束（进现场识别，而非拍脑袋）

用户场景：开会中需要用英语汇报项目状态、回应主管追问。会一点英语，但真实会议时脑子一片空白→反应慢→越练越怕。现有方案要么背词（考完忘）、要么口语课（贵、慢、不可量化）。

进现场后定的产品判断（不是关起门来定）：

  • 核心假设不是账户，而是"明天回来能继续从昨天的 Day/Step 练"——用户退出后能恢复进度比注册账号优先 100 倍。先解决本地持久化，账户是第⑤步的自动化。
  • 反应时间方法学要诚实：训练反应力的关键是「听到提问→开口时间」，不是「说话总时长」。原代码按后者计时，方法学就是错的。
  • 展示数据必须从真实训练记录派生：roadmap profile / 复习队列 / 日报完成度不能写死假话，否则用户每天看假数据会自我麻痹。
  • 真机优先：手机经局域网 IP 访问 dev server 是 http（非安全上下文），浏览器直接锁死麦克风/通知权限——这个边界必须先解决，不能只让本地浏览器能跑。
  • 隐私友好：只存文本评分，不存原始音频；本地兜底保证弱网可用。

3. 三个关键工程问题（进现场才暴露）

① 反应时间方法学修正

原代码用「按住→松开」=说话时长，是测「说话快慢」，不是测「反应快慢」。训练反应力的核心指标是错的。修复：拆 runRecognition(onFinal) 通用内核，用 questionShownAtRef 锁定「训练卡片出现」时间，首次 onresult 触发即锁定反应时间，responseSecondsRef 解决闭包读到旧值的 bug——drill 与 diagnostic 共用同一计时源，不分叉。

② 数据闭环假数据修正

roadmap profile / 复训队列 / 日报完成度 全部写死：「明天练习 X」/「已完成 4 轮反应训练」都是模板字符串，与用户实际训练无关。第一性拆解：账户≠持久化。修复：业务层只依赖 StorageAdapter 接口，LocalAdapter（默认兜底）+ CloudBaseAdapter（env 配齐自动启用）运行时切换，业务零改动。所有展示数据从 records 派生（derive.js），加新功能只需写新派生函数。

③ 安卓真机按住说话跑稳

桌面浏览器能跑的按住说话，到安卓真机会被 pointercancel 事件卡住，识别器不结束 → recording stuck true → 用户感觉"还没按就在聆听"。同时麦克风/通知权限被浏览器因非安全上下文（局域网 http 访问）锁死，图标灰、无法改。修复链：

  • 麦克风加 onPointerCancel={stopListening} + 切屏 effect 重置 recording 和 recognitionRef。
  • 识别器 continuous=true（不是 false）+ 重复 start guard + onerror 分流（aborted 静默 / not-allowed 明确提示 / 其他交 onend）。
  • 麦克风按钮 CSS 加 touch-action:none; user-select:none; -webkit-tap-highlight-color:transparent，防触发滚动/选中文本/长按菜单。
  • next.config.mjs 加 output:'export' → npm run build → tcb hosting deploy，部署到 CloudBase HTTPS 域名，满足安全上下文，权限可正常弹窗授权。
  • 全局禁用文本选择 + document 拦截 contextmenu 事件：修安卓长按页面元素弹出"复制/分享/全选/搜索/翻译"系统菜单覆盖麦克风按钮的 bug。

附：完成度真实性双保险（v1.3.3）

第一版让用户一路点"下一步"到完成页且显示"已练习/已完成"——这是流程漏洞。修复：「下一步」按钮 disabled={!当前 step 有真实记录}，最后一步需 4 步全练过才可提交；report 页加未完成态兜底（即使绕过按钮也只显示"尚未完成" + 返回继续训练）。遵循"展示数据全部从真实记录派生"约定，不引入新 state，判定逻辑用 records.filter(r => r.day===day).some(r => r.step===step) 一行派生。

4. 交付与结果

交付物：一个完整可运行的 7 天训练 Web app（Next.js 15 + React 19 + CloudBase），移动端 + 桌面端通用，可加主屏做 PWA 全屏使用。已部署到 HTTPS 域名（https://workbuddy-d3grq7ueha21321e5-1464119629.tcloudbaseapp.com），手机浏览器打开即可使用麦克风与通知。

结果：

  • 把"会一点英语但开会不敢开口"拆成可量化训练（反应时间 / 任务完成度 / 待巩固队列），用户每天看到真实数据而非假话。
  • 账号回流路径已铺好：当前 LocalStorage 兜底，配 NEXT_PUBLIC_CLOUDBASE_ENV + ACCESS_KEY 即可启用匿名登录，电脑/手机共享同一份数据，无需重写业务层。
  • 邀请裂变做成真实闭环（本地 registry + 云端 invites 集合）：分享码 → 朋友完整体验 7 天 → 解锁高级成长报告。
  • 并发就绪：每用户独立 doc + version 自增，为多设备乐观锁/CAS 打底；MVP 阶段用户量不到堆队列阈值。

迭代节奏：从接 codex 接力到 v1.3.3 共 14 个版本（数据闭环 / 邀请裂变 / 诊断语音接线 / 提醒 MVP / 连续识别修复 / 权限屏蔽引导 / 安卓触屏 / 移动端部署 / 长按菜单屏蔽 / 完成度真实性双保险……）。每个版本都经过真机验证，并且记进项目记忆、Obsidian 和 ima，三处保持同源；也守着我自己的"复用纪律"——只复用方法论，不复用具体细节。
